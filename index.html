Project C

May 2025 - team of 3 - 3 weeks

CGitLab

The goal was to build a graphical interface by writing a software library from scratch in C. We started from a short documentation describing the steps ahead and a couple of given functions - one to open a window, another returning a pointer to the pixel at coordinates (0, 0) of a surface.

From those two building blocks, we wrote our own drawing functions: a line, several lines, a polygon, a curve, and text. Clipping needed special care here - a window dragged outside the screen, or two windows overlapping, both had to render correctly rather than crash or corrupt memory.

Once drawing worked, we moved to interaction: detecting clicks on a button, closing a window. The library was solid enough by the end to run full test games, including a working puzzle.

Object-Oriented Programming - Boids

November 2025 - team of 2 - 10h+ outside class

JavaGitLab

This project studied systems that simulate the movement of agents in swarms. I focused on boids: an agent's behavior depends on the position and orientation of the agents around it, meaning those close enough and within its field of view. The model rests on three rules - cohesion, an agent moves toward the average position of its neighbors; alignment, it tends to move in the same direction as them; and separation, agents that get too close repel each other to avoid collisions.

Our implementation used a class Agents, holding lists of each agent's position and speed, and a class Boids inheriting from it, plus a BoidsSimulator class handling the drawing. The Boids class defines a whole group and predicts each boid's next position by summing the forces applied to it, which meant keeping an up-to-date list of neighbors for every boid at all times.

3D Graphic Project

April 2026 - team of 3 - 12h in class + 10h+ outside class

PythonGitLab

The goal was to improve the rendering pipeline seen in class practicals. We chose to implement planar reflection, which produces a mirror image of a scene on a single plane. Our method was to create a virtual camera symmetrical to the real one relative to the reflecting surface, render the scene from that camera, clip the view to keep only the part actually reflected by the mirror, render the scene again at the mirror's position, and finally render the rest of the scene.

Object Analysis and Design

May 2026 - team of 3 - 30h+ outside class

JavaLibGDXGitLab

The brief was intentionally vague: design a game, playable in a terminal or with a simple editor, and deliver documentation explaining how it was conceived. The real point of the exercise was to conceptualize a piece of software end to end using diagrams, before writing a single line of code.

We started with specifications to fix the gist of the game, then wrote an analysis and a design document to pin down what the software actually needed to do. Only then did we move to implementation, coding in Java with LibGDX to handle game interactions, and sourcing free assets for the visuals.

The class diagram and the codebase kept feeding back into each other - details we'd missed on paper surfaced once we started building, sending us back to revise the design. We closed the project with a user manual and a self-assessment of the final product.

2-Month Internship - Dassault Systemes

June-July 2026 - Cybersecurity IS team

PythonSQLAlchemySQLDockerDocker ComposeWSLHTMLGitLab

In summer 2026, I joined the cybersecurity IS team of Dassault Systemes for two months. I was assigned to the development of a new version of the team's reference website, the Vulnerability Operation Center (VOC). The VOC used to store retrieved data in a cache, but I was asked to move it to a database so that the database would become the sole source of truth - a change that also opens the door to future improvements of the VOC.

In practice, I carried out the following steps: connecting the database with SQLAlchemy and retrieving the data stored inside it; connecting the database to the VOC so that, given a populated database, the cache could be rebuilt from it; connecting the database to various external APIs to populate it; managing database updates - inserting, modifying or deleting information; preparing database backups; and finally removing the cache.

Since I finished the core of my internship earlier than expected, I also built a new feature for the VOC: a scheduling tool. It was needed because Dassault Systemes' cybersecurity teams were going through a reorganization and my team was about to grow. The user enters the number of person-days required and a timeframe to search within, and the feature returns the available pentesters along with matching dates.
