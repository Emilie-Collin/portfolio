Project C

May 2025 · team of 3 · 3 weeks

The goal was to build a graphical interface by writing a software library from scratch in C. We started from a short documentation describing the steps ahead and a couple of given functions — one to open a window, another returning a pointer to the pixel at coordinates (0, 0) of a surface.

From those two building blocks, we wrote our own drawing functions: a line, several lines, a polygon, a curve, and text. Clipping needed special care here — a window dragged outside the screen, or two windows overlapping, both had to render correctly rather than crash or corrupt memory.

Once drawing worked, we moved to interaction: detecting clicks on a button, closing a window. The library was solid enough by the end to run full test games, including a working puzzle.

Object Analysis and Design

May 2026 · team of 3 · 15h in class + 20h+ outside

The brief was intentionally vague: design a game, playable in a terminal or with a simple editor, and deliver documentation explaining how it was conceived. The real point of the exercise was to conceptualize a piece of software end to end using diagrams, before writing a single line of code.

We started with specifications to fix the gist of the game, then wrote an analysis and a design document to pin down what the software actually needed to do. Only then did we move to implementation, coding in Java with LibGDX to handle game interactions, and sourcing free assets for the visuals.

The class diagram and the codebase kept feeding back into each other — details we'd missed on paper surfaced once we started building, sending us back to revise the design. We closed the project with a user manual and a self-assessment of the final product.
